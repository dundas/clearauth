## Key Learnings

### parseCookies correctness is critical
`split('=')` truncates base64-padded values. Always use `indexOf('=')` and `slice` for cookie parsing. This was a BLOCKING review finding.

### email_verified must be explicitly threaded
It's easy to add `email_verified` to an interface but forget to wire it through. Every call site to `createAccessToken` needs the claim passed explicitly. Check: `handleTokenRequest`, `handleRefreshRequest`, `issueTokenPair`.

### revokeRefreshToken mock tests need `rows` array
`executeTakeFirstOrThrow` expects `rows[0]` in the response. A mock returning only `{success: true, rowCount: 1}` without `rows: [{...}]` will throw.

### Roborev exit code 1 ≠ errors only
Roborev exits 1 when it finds issues of ANY severity, including Low. Track severity in output to decide whether to block or note.

### CodeRabbit "validateSession parameter order" is a false alarm
CodeRabbit repeatedly flagged `(db, sessionId)` vs `(sessionId, db)`. All internal callers use `(db, sessionId)` consistently. The function was always db-first. Ignore this specific finding.

### Semgrep `unsafe-formatstring` on console.error
Flags `console.error(variable + ' text:', error)` as security finding. Use `// nosemgrep` comments on lines with internal string concatenation where the variable is always a compile-time constant.

### JWT logout requires both cookie clearing AND DB revocation
Clearing the cookie without revoking the DB record leaves the refresh token valid. `revokeRefreshTokenByValue` does a single idempotent UPDATE — preferred over getRefreshToken + revokeRefreshToken (two-step).
